# Talos Homelab Design

## Context

Single physical machine homelab. Goal: elegant, reproducible workflow combining PXE boot, GitOps, and infrastructure-as-code. Repo is public.

## Stack

| Layer | Tool | Role |
|---|---|---|
| PXE | dnsmasq + Talos release assets | Boot Talos into maintenance mode |
| OS | Talos v1.13 | Immutable, API-only OS |
| IaC | OpenTofu + provider `siderolabs/talos` | Config generation, secrets, bootstrap |
| GitOps | Flux CD | Kubernetes workloads from git |
| Secrets | SOPS + age | At-rest encryption in git |
| Tooling | mise | Tool version management (opentofu, talosctl, flux, kubectl, sops, age) |
| Hooks | hk | Pre-commit checks (lint, format, secret detection) |

## Architecture

### Provisioning flow (day 0)

```
Machine reboot → PXE (dnsmasq → vanilla Talos assets) → Talos maintenance mode
                                                         │
                                               tofu apply (local)
                                                 ├─ generates secrets + machineconfig
                                                 ├─ pushes config via Talos API (insecure, maintenance only)
                                                 ├─ bootstraps etcd (once)
                                                 └─ retrieves kubeconfig → local file

kubectl create secret (age key → flux-system namespace)
flux bootstrap github → Flux installed → reconciles kubernetes/ from git
```

### Reprovisioning flow (day 2)

```
talosctl reset --reboot → PXE → maintenance mode → tofu apply → cluster restored
```

### GitOps flow (ongoing)

```
git push → Flux reconcile → workloads applied to cluster
```

## PXE Boot

dnsmasq is configured on the dedicated network server (pfSense/OPNsense/dnsmasq host). This config lives on that server, not in this repo.

Talos vanilla assets (`vmlinuz-amd64`, `initramfs-amd64.xz`) are downloaded from the GitHub releases page and served locally via TFTP, or referenced directly via UEFI HTTP boot:

```ini
# dnsmasq config on network server
dhcp-host=<mac>,<node-ip>,homelab,infinite

# UEFI HTTP boot — assets served locally or from GitHub releases
dhcp-match=set:efi-http,option:client-arch,16
dhcp-option=tag:efi-http,option:bootfile-url,http://<server>/talos/v1.13.0/vmlinuz-amd64
```

Assets can be cached locally in `pxe/` (gitignored) to avoid depending on GitHub availability at boot time.

No `talos.config=` kernel parameter — OpenTofu pushes config directly to the maintenance mode API, avoiding the need to publish machineconfig to a URL before booting.

### Image Factory — when needed

Image Factory (`factory.talos.dev`) is only required if system extensions are needed (e.g. `intel-ucode`, `iscsi-tools`). At that point, add `talos/schematic.yaml` to the repo, submit it to Image Factory to get a schematic ID, and update the dnsmasq boot URL to point to the Image Factory PXE endpoint. This is a future step, not part of the initial setup.

## OpenTofu

### Variables

Node IP and cluster name are variables, never hardcoded. Real values live in `terraform.tfvars` (gitignored).

```hcl
# tofu/variables.tf
variable "node_ip" {
  description = "IP address of the Talos node"
  type        = string
}

variable "cluster_name" {
  description = "Kubernetes cluster name"
  type        = string
  default     = "homelab"
}
```

### `tofu/main.tf` structure

1. `talos_machine_secrets` — generates CA, tokens, etcd keys. Stored in OpenTofu state (never in git).
2. `talos_machine_configuration` (controlplane) — renders machineconfig with patches applied.
3. `talos_machine_configuration_apply` — pushes config to node via Talos API (`apply_mode = "reboot"`).
4. `talos_machine_bootstrap` — bootstraps etcd. Runs once; subsequent applies are no-ops.
5. `talos_cluster_kubeconfig` — writes kubeconfig locally (gitignored).

### State

OpenTofu state contains Talos secrets. Options:
- **Local** (`terraform.tfstate`, gitignored) — sufficient for a solo homelab
- **Remote** (S3-compatible backend: Minio, Cloudflare R2) — recommended if working from multiple machines

State is never committed to git.

### Patches

```yaml
# talos/patches/all.yaml
machine:
  network:
    hostname: homelab
  time:
    servers:
      - time.cloudflare.com
      - pool.ntp.org
```

```yaml
# talos/patches/controlplane.yaml
- op: add
  path: /cluster/allowSchedulingOnControlPlanes
  value: true
```

No IPs or network-specific values in committed patch files.

## Flux CD

Bootstrapped once after `tofu apply` completes:

```bash
flux bootstrap github \
  --owner=<owner> \
  --repository=homelab \
  --branch=main \
  --path=kubernetes/flux-system \
  --personal
```

`apps/` depends on `infrastructure/` via Flux `dependsOn`, ensuring CNI and core services are ready before workloads are applied.

### Secrets

Kubernetes secrets are encrypted with SOPS + age. Flux decrypts natively at apply time.

```yaml
# .sops.yaml
creation_rules:
  - path_regex: kubernetes/.*\.secret\.yaml
    age: <public-key>
```

The age private key lives locally (gitignored). Never committed.

Flux must be told about the age key to decrypt secrets at reconcile time. After `flux bootstrap`:

```bash
cat age.key | kubectl create secret generic sops-age \
  --namespace=flux-system \
  --from-file=age.agekey=/dev/stdin
```

Flux's Kustomization resources must then reference this secret via `spec.decryption`.

## Developer Tooling

### mise — `mise.toml`

All CLI tools are pinned and installed via mise. No manual installation required on a new machine.

```toml
[tools]
opentofu    = "latest"
talosctl    = "latest"
kubectl     = "latest"
flux2       = "latest"
sops        = "latest"
age         = "latest"

[tasks.apply]
description = "Provision or update the Talos node"
run         = "tofu -chdir=tofu apply"

[tasks.reset]
description = "Wipe and reprovision the node"
run         = "talosctl reset --reboot --nodes {{ env.NODE_IP }}"
```

`mise install` on a fresh clone pulls every tool at the pinned version. Tasks (`mise run apply`) provide a discoverable interface without a separate Makefile.

### hk — `hk.pkl`

Pre-commit hooks run automatically on `git commit`. Configuration uses pkl.

```pkl
amends "package://github.com/jdx/hk/releases/download/v1.46.0/hk@1.46.0#/Config.pkl"
import "package://github.com/jdx/hk/releases/download/v1.46.0/hk@1.46.0#/Builtins.pkl"

local steps = new Mapping<String, Step> {
    // Terraform format check
    ["tofu-fmt"] {
        glob = List("tofu/**/*.tf")
        check = "tofu -chdir=tofu fmt -check"
        fix   = "tofu -chdir=tofu fmt"
    }
    // Detect unencrypted SOPS files (*.secret.yaml must have sops metadata)
    ["sops-check"] {
        glob  = List("kubernetes/**/*.secret.yaml")
        check = "for f in {{files}}; do grep -q 'sops:' $f || (echo \"$f is not SOPS-encrypted\" && exit 1); done"
    }
    // YAML lint for Kubernetes manifests and Talos patches
    ["yaml-lint"] {
        glob  = List("kubernetes/**/*.yaml", "talos/**/*.yaml")
        check = "yamllint {{files}}"
    }
    // Built-in: detect private keys committed by mistake
    ["no-private-keys"] = Builtins.check_private_key
}

hooks {
    ["pre-commit"] {
        stash = "git"
        stage = true
        steps = steps
    }
}
```

`hk install` wires the hooks into `.git/hooks/`. The `sops-check` step is the critical guard ensuring no secret ever lands in git unencrypted.

## Security Notes

- Repo is public: no IPs, no secrets, no kubeconfig are ever committed.
- `terraform.tfvars`, `terraform.tfstate`, `*.tfstate.backup`, `kubeconfig.yaml`, `age.key` are all gitignored.
- Talos API is mTLS — the maintenance mode insecure window is limited to the time between PXE boot and `tofu apply`.
- Talos has no SSH, no shell: attack surface is minimal by design.

## What is NOT automated (day 0 manual steps)

1. `mise install` — install all tools at pinned versions.
2. `hk install` — wire pre-commit hooks.
3. `age-keygen -o age.key` + fill `.sops.yaml` with the public key.
4. Download Talos assets → configure dnsmasq on network server to serve them.
5. Boot machine via PXE → wait for Talos maintenance mode (API on :50000).
6. Copy `tofu/terraform.tfvars.example` → `tofu/terraform.tfvars`, fill in values.
7. `mise run apply` (`tofu apply`).
8. `flux bootstrap github` once after cluster is up.
9. Push age key to cluster: `kubectl create secret generic sops-age --namespace=flux-system --from-file=age.agekey=age.key`.

All subsequent operations (workload changes, Talos config patches, upgrades) are driven from git.
