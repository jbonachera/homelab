# Infrastructure Operators to Terraform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move MetalLB, Traefik, External Secrets Operator, and NFS provisioner from Flux HelmReleases to Terraform `helm_release` resources, eliminating CRD timing races at the structural level.

**Architecture:** Terraform installs operators imperatively via `helm_release` (blocking until `Ready` + CRDs registered). Flux retains only the Custom Resources that consume those CRDs (MetalLB pool config, Traefik IngressRoute, ESO stores, TimescaleDB workload). The `hashicorp/helm` provider reuses the `kubeconfig.yaml` already generated by the Talos provider.

**Tech Stack:** OpenTofu, hashicorp/helm ~> 2.16, Flux CD v2, Talos Linux

### Task 1: Add Helm provider and operator variables to Terraform

**Goal:** Wire `hashicorp/helm` provider into `tofu/` and declare chart version + NFS variables.

**Steps:**

- [ ] **Step 1: Update `tofu/main.tf` — add helm provider**

Replace the `terraform {}` block and append the provider:

```hcl

      source  = "siderolabs/talos"
      version = "~> 0.11"

      version = "~> 2.5"

    helm = {
      source  = "hashicorp/helm"
      version = "~> 2.16"

}
```

### Task 2: Create operators.tf with 4 helm_release resources

**Goal:** Declare MetalLB, Traefik, External Secrets Operator, and NFS provisioner as Terraform `helm_release` resources.

**Files:**
- Create: `tofu/operators.tf`

**Acceptance Criteria:**
- [ ] `tofu/operators.tf` contains exactly 4 `helm_release` resources: `metallb`, `traefik`, `external_secrets`, `nfs_provisioner`
- [ ] All releases set `wait = true`
- [ ] MetalLB, Traefik, ESO have `depends_on = [talos_machine_bootstrap.this]`
- [ ] NFS provisioner has `depends_on = [helm_release.traefik]`
- [ ] All Helm values from the existing HelmRelease YAMLs are preserved
- [ ] `tofu validate` passes

**Verify:** `cd tofu && tofu validate` → `Success! The configuration is valid.`

**Steps:**

- [ ] **Step 1: Create `tofu/operators.tf`**

```hcl
resource "helm_release" "metallb" {
  depends_on       = [talos_machine_bootstrap.this]
  name             = "metallb"
  repository       = "https://metallb.github.io/metallb"
  chart            = "metallb"
  version          = var.chart_metallb_version
  namespace        = "metallb-system"
  create_namespace = true
  wait             = true
  wait_for_jobs    = true

  values = [
    yamlencode({
      speaker = {
        ignoreExcludeLB = true
      }
    })
  ]
}

resource "helm_release" "traefik" {
  depends_on       = [talos_machine_bootstrap.this]
  name             = "traefik"
  repository       = "https://traefik.github.io/charts"
  chart            = "traefik"
  version          = var.chart_traefik_version
  namespace        = "traefik-system"
  create_namespace = true
  wait             = true
  wait_for_jobs    = true

  values = [
    yamlencode({
      service = {
        type = "LoadBalancer"
      }
      ports = {
        web = {
          exposedPort = 80
        }
      }
      ingressRoute = {
        dashboard = {
          enabled = false
        }
      }
      ingressClass = {
        name = "traefik"
      }
      providers = {
        kubernetesCRD = {
          enabled = true
        }
        kubernetesIngress = {
          enabled = true
        }
      }
    })
  ]
}

resource "helm_release" "external_secrets" {
  depends_on       = [talos_machine_bootstrap.this]
  name             = "external-secrets"
  repository       = "https://charts.external-secrets.io"
  chart            = "external-secrets"
  version          = var.chart_eso_version
  namespace        = "external-secrets"
  create_namespace = true
  wait             = true
  wait_for_jobs    = true

  values = [
    yamlencode({
      installCRDs = true
    })
  ]
}

resource "helm_release" "nfs_provisioner" {
  depends_on       = [helm_release.traefik]
  name             = "nfs-subdir-external-provisioner"
  repository       = "https://kubernetes-sigs.github.io/nfs-subdir-external-provisioner"
  chart            = "nfs-subdir-external-provisioner"
  version          = var.chart_nfs_version
  namespace        = "nfs-provisioner"
  create_namespace = true
  wait             = true
  wait_for_jobs    = true

  values = [
    yamlencode({
      nfs = {
        server = var.nfs_server
        path   = var.nfs_path
      }
      storageClass = {
        name          = "nfs-client"
        defaultClass  = true
        reclaimPolicy = "Retain"
        mountOptions  = ["hard", "nfsvers=4.1", "noatime"]
      }
    })
  ]
}
```

### Task 4: Simplify Flux dependency chains

**Goal:** Remove the `dependsOn` entries that referenced the now-deleted Flux Kustomizations, and add a `healthChecks` entry to `timescaledb-config` so Flux waits for the `ExternalSecret` to be `Ready` before marking infrastructure complete.

**Files:**
- Modify: `kubernetes/infrastructure/timescaledb.yaml`
- Modify: `kubernetes/infrastructure/timescaledb-config.yaml`

**Acceptance Criteria:**
- [ ] `timescaledb.yaml` has no `dependsOn` (NFS StorageClass and ESO are guaranteed present via Terraform before Flux starts)
- [ ] `timescaledb-config.yaml` has `dependsOn: [{name: timescaledb}]` only (no `external-secrets` entry)
- [ ] `timescaledb-config.yaml` has `healthChecks` on the `ExternalSecret` object
- [ ] `mise exec -- yamllint kubernetes/` passes

**Verify:** `mise exec -- yamllint kubernetes/` → no errors

**Steps:**

- [ ] **Step 1: Rewrite `kubernetes/infrastructure/timescaledb.yaml`**

Remove both `dependsOn` entries. The `nfs-client` StorageClass and ESO are now guaranteed present by Terraform before Flux reconciles.

```yaml
---
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: timescaledb
  namespace: flux-system
spec:
  interval: 10m0s
  path: ./kubernetes/infrastructure/timescaledb
  prune: true
  sourceRef:
    kind: GitRepository
    name: flux-system
```

- [ ] **Step 2: Rewrite `kubernetes/infrastructure/timescaledb-config.yaml`**

Remove `dependsOn: external-secrets` (ESO is now a Terraform resource, not a Flux Kustomization). Keep `dependsOn: timescaledb` so the RBAC and namespace exist before ESO tries to read secrets. Add `healthChecks` so Flux waits for the ExternalSecret to reach `Ready` status before marking infrastructure complete — this unblocks `home-assistant` reliably.

```yaml
---
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: timescaledb-config
  namespace: flux-system
spec:
  interval: 10m0s
  path: ./kubernetes/infrastructure/timescaledb-config
  prune: true
  wait: true
  timeout: 5m0s
  sourceRef:
    kind: GitRepository
    name: flux-system
  dependsOn:
    - name: timescaledb
  healthChecks:
    - apiVersion: external-secrets.io/v1beta1
      kind: ExternalSecret
      name: timescaledb-credentials
      namespace: database
```

## Bootstrap Sequence Reference

After implementation, the from-scratch workflow is:

```
1. Fill in tofu/terraform.tfvars (node_ip, nfs_server, nfs_path, etc.)

2. tofu apply
   → Talos: secrets, machineconfig, bootstrap, kubeconfig.yaml
   → Operators: MetalLB, Traefik, ESO, NFS (blocking until Ready)

3. Flux auto-reconciles:
   → metallb-config  (IPAddressPool, L2Advertisement)
   → traefik-config  (IngressRoute dashboard)
   → timescaledb     (StatefulSet, Service, ConfigMap)
   → timescaledb-config (Password, ClusterSecretStore, ExternalSecret → secret created)
   → home-assistant  (dependsOn: infrastructure)
```

No manual `kubectl apply` steps required.
